# Architecture
Links reserves pools for an Identity organization. A visitor may subscribe while a link has no destination; the first activation records durable email work alongside the URL update.

Dependency direction is interfaces → platform → contexts → kernel. Context domain/application modules contain no FastAPI, Pydantic, SQL, Redis or SMTP infrastructure. The platform composition root uses dependency-injector and shared_messaging CommandBus/QueryBus with a PostgreSQL command UoW; queries run in read-only transactions. Context contracts publish intents and DTOs. The existing Container owns handler, bus and operator construction; application ports depend on DTOs/domain values rather than intent packages.

OrganizationId comes directly from shared_identity. Links owns lnk (link), lpl (pool) and lsb (subscription) CanonicalId types. Public IDs use compact UUIDv7 strings; PostgreSQL stores native UUID columns generated by uuidv7(). Public short codes remain stable and globally unique.

HTTP adapters map into shared `RequestContext`, `ActorContext`, `OperationContext` and `TraceContext`; audit records preserve their lineage. Shared field normalizers handle local dataclass fields and explicit code enforces cross-field invariants. The PostgreSQL tenant selector is `plazia.organization_id`.

Protected mutations serialize on durable receipts scoped by issuer, organization, subject, command and key. Fingerprints cover canonical command values, and typed snapshots replay the original response. Receipts, state, audit and mail jobs share the command transaction. Shared HAL and page-token contracts provide forward navigation; `ApiContract` owns the versioned base and resource audience validation.

One Flyway authority owns access, links and platform schemas. V1 defines the fresh schema; V2 grants organization-scoped pool management and cascades pool deletion to its links. Applied V1 stays unchanged, and only verified packaged history prefixes are admitted for migration. Runtime requires the complete current history. There is no ORM, Alembic, SQLite or legacy workspace compatibility layer. The API role has organization RLS for management data and narrow security-definer functions for public resolution/subscription. It cannot read subscriber addresses or mail jobs. Public functions have fixed search paths and revoked PUBLIC execution. The worker has a separate role. Startup verifies schema state without migrating.

Pool renaming changes only the display name. Pool deletion removes all its links, their subscriptions and queued emails in one transaction. Bulk deletion names 1–100 explicit canonical link IDs, optionally restricted to one pool. It locks rows in ID order and requires every selected link to exist in the organization and pool before deleting any. Missing, foreign or stale selections fail as a whole. Both deletion flows share the existing receipt and audit boundary; individual link deletion reuses the same repository path.

Subscription and activation lock the same link row. If subscription wins, activation queues it. If activation wins, the visitor sees that the link is ready and no email is recorded. Duplicate normalized subscriptions and jobs have unique constraints. An activation command, its jobs and audit entry commit atomically before an HTTP success response. Later destination edits do not queue another activation.

The independent worker claims one ready email with SKIP LOCKED and holds that job transaction through bounded SMTP delivery. Failures retry up to five attempts with capped backoff. A crash after SMTP accepts the message but before commit may send a duplicate; delivery is at least once. Delivered/dead subscriber records are purged after 30 days; stale pending subscriptions without deliverable work after 365 days.

OAuth client capabilities use links:read/create/update/delete. OpenFGA organization reader authority permits reads; manager permits writes. Identity owns membership tuples, Links does not mint them. Authority is checked before scoped repositories are opened, then an active local issuer+organization binding is required. The shared `plazia_authlib.authz` registry maps Links actions to these Identity-owned organization relations. Links uses the shared OpenFGA adapter and retains its local scope and active-binding guards.

Browser sign-in uses authorization code + PKCE, nonce, server-side Redis sessions, bounded TTL and CSRF-protected forms. DPoP tokens require proof bound to the method, configured canonical origin/path, access-token hash and Redis replay consumption. Shared `plazia_authlib.authn` validates Identity's RFC 9068 access tokens and OIDC ID tokens. Links owns canonical principal mapping, browser sessions and replay storage, and closes its verifier transport at runtime shutdown.

See [implementation decisions](../.codex/specs/link-pools/decisions.md) and [drift audit](../.codex/specs/link-pools/drift.md).

Request statistics remain owned by Links. Public resolution is a pure query;
the HTTP adapter then dispatches a separate anonymous `RecordVisitCommand` in
a writable UoW, with a 250 ms capture budget and fail-open response behavior.
The existing SQL repository records atomic increments through a fixed-search-path
security-definer function that verifies link ID, code, enabled state and outcome.
A tenant-scoped aggregate and global collection-start marker replace individual
visit storage. Deletion cascades clear aggregates. No visitor data or new worker
is introduced, and telemetry is not the business source of truth.

The existing read handlers batch projections for their resource IDs. Read-specific
DTOs and HTTP schemas add statistics without changing mutation receipts or replay
representations. `GetStatisticsQuery` uses the same read authority and active
organization binding as the resource reads. Queries stay in read-only transactions;
statistics errors produce a stable 503 instead of fabricated zeros. Flyway V3
and startup admission own the new policy, function, grants and cascade contract.
Subscriber counts reuse the tenant-scoped subscriptions table in the same batched
projection. V4 grants the API SELECT on organization/link IDs only; email and other
subscription columns remain private. Counts reflect currently retained subscriptions. The batch query aggregates only selected links, and startup rejects unauthorized table/column writes and PUBLIC grants.

Runtime composition uses shared passive observability providers and HTTP instrumentation. Activation jobs carry bounded W3C context across the durable handoff. Enqueue, consumer and SMTP spans describe latency; bounded outcome metrics distinguish sent, retry and dead settlement. Worker gauges sample pending/dead jobs, oldest eligible age and active leases without recipient/tenant dimensions. Terminal logs classify errors without their messages or payloads. Export failure does not change command or delivery results.
