# Decisions
- Organization owns pools. Identity owns canonical tenant IDs, subjects and membership authority; Links stores only an explicit issuer+organization activation binding.
- Fresh Flyway V1 only. No customer data exists. Remove ORM/Alembic and inherited workspace/marketing/legacy auth implementation; do not retain parallel compatibility paths.
- Python 3.14 matches the actual shared package runtime floor/ceiling.
- Use plazia-kernel CanonicalId/CanonicalIds and AnnotatedFields normalizers, plazia-contracts OrganizationId, plazia-persistence PostgreSQL runtime, shared messaging CQRS/UoW, shared settings sources and shared SMTP transport.
- Native UUIDv7 keys generated by PG18, compact canonical IDs on wire. lnk/lpl/lsb prefixes have no collisions in the bounded current ecosystem scan. Generated public codes are eight opaque characters; custom codes allow 3–10 characters.
- NULL destination is reserved, enabled flag distinguishes disabled. Activation requires an enabled link. Same-row locking serializes subscription with activation. A separate platform activation_emails queue stores one durable job per subscription.
- Organization authority uses the existing OpenFGA reader/manager relations before protected database scope. Product-specific Links registry publication remains a named ecosystem gap; do not impersonate another product action or alter sibling models silently.
- Retain adopted RS256 RFC9068 access-token validation and OAuthlib PKCE adapter because the shared-session authlib verifier is a different wire contract. Generic IDs, normalization, authorization subjects, persistence and delivery use shared packages.
- SMTP transport is at least once; the unavoidable acceptance/commit crash window can duplicate mail. Five attempts, capped exponential backoff, no subscriber PII in API/logs, separate worker role.
- No local-memory auth/replay/admission fallback, no trusted arbitrary forwarded Host/IP, no outbound destination fetch at registration.
- Every protected mutation requires a caller-scoped key. Receipt claims, state, audit and typed response snapshots commit together, with authority rechecked on replay. Collections use shared HAL and opaque bound forward tokens; ApiContract owns /api/v1 and canonical audiences.
- Runtime uses shared passive HTTP/OTLP providers and Links-owned bounded queue signals. Jobs persist W3C handoff context; terminal delivery outcomes follow transaction commit. Local evidence does not prove collector ingestion.
